# 미팅 준비 비서 디자인 구현 가이드

버전 1.1 | 2026-10-27 | 개발 명세 v1.8 및 authentication-spec.md와 함께 적용

## 1 적용 범위와 결정 사항

공모전용 Android 휴대폰 앱과 Pleos 차량 앱을 하나의 Expo 프로젝트로 구현한다. 웹 서비스는 만들지 않는다. 흰색 배경·파란색 강조·짙은 남색 글자를 사용한다. `온유`는 임시 서비스명이며 확정 상표가 아니다.

시안 `design-preview.html`에서 휴대폰 / Pleos 차량과 넓은 창 / 분할 창 / 낮은 창을 전환한다. HTML은 레이아웃 참고 자료이며 실제 앱 코드는 React Native로 구현한다. 브라우저 시안을 WebView로 포장하지 않는다. 브리프를 기본 제품 구조로 사용하고, 컨버세이션은 미팅 상세의 대화 화면 참고로 사용한다. 두 시안을 서로 다른 제품·앱으로 만들지 않는다.

우선순위: 사용자 수정 지시 → 이 가이드와 development-spec.md → HTML 시안. HTML의 샘플 동작·수치는 실제 데이터·SDK 동작을 보장하지 않는다. 이 가이드의 크기와 분기점은 제품 설계 기본값이며 Pleos 공식 최소값으로 주장하지 않는다. 실제 차량 가이드가 더 엄격하면 플랫폼 요건에 맞춘다.

## 2 색상과 디자인 토큰

`design-tokens.json`을 앱 테마의 기준으로 옮긴다. CSS px는 미리보기 단위이고 실제 앱 배치는 React Native 논리 단위(dp), 글자는 시스템 글자 배율을 반영한다.

| 용도 | 색상 | 사용 규칙 |
|---|---|---|
| 배경·카드 | #FFFFFF | 기본 화면과 콘텐츠 배경 |
| 주요 글자 | #16243B | 제목·본문·핵심 수치 |
| 보조 글자 | #63738B | 시간·위치·출처·상태 설명 |
| 브랜드·주요 버튼 | #2563EB | 화면당 주요 행동 1개, 활성 탭 |
| 강조 배경 | #EDF4FF | 선택 상태·담당자 아바타·자료 아이콘 |
| 구분선 | #E1E8F2 | 1dp 테두리·행 구분 |
| 버튼 위 글자 | #FFFFFF | 파란 버튼 위 라벨 |
| 오류 | #B42318 | 실패 메시지·재시도 안내. 색만으로 구분하지 않음 |

녹색·베이지 중심 테마는 사용하지 않는다. 이번 기본 시안은 라이트 테마다. 야간 테마는 현재 제작 범위에 포함하지 않으며, 차량 밝기·야간 정책 대응은 실제 환경에서 별도 검증한다.

폰트는 Android 기본 한국어 지원 sans-serif를 우선한다. 별도 폰트 다운로드에 의존하지 않는다. 일반 400, 강조 500~600. 아이콘은 동일한 선형 아이콘 체계로 통일한다.

| 스타일 | 휴대폰 크기 / 행간 | 차량 크기 / 행간 |
|---|---|---|
| 화면 제목 | 26 / 35 | 28 / 38 |
| 섹션 제목 | 18 / 26 | 22 / 31 |
| 핵심 브리핑 | 16 / 26 | 26 / 40 |
| 본문 | 15 / 23 | 20 / 30 |
| 보조 정보 | 12 / 18 | 16 / 24 |
| 버튼 | 15 / 22 | 20 / 28 |

폰트 크기는 창에 맞춰 무작정 축소하지 않는다. 글자 배율 1.0·1.3에서 배치와 버튼 높이를 검증한다. 시안의 작은 출처·영문 장식 라벨은 실제 차량 핵심 UI에서는 제거하거나 위 표 기준으로 확대한다.

간격은 4, 8, 12, 16, 20, 24, 32 단위. 휴대폰 외곽 20, 차량 기본 24·좁은 창 20·낮은 창 16. 카드 모서리 20, 버튼 12, 배지 8. 그림자는 약하게 사용하며 제품 화면 안에 휴대폰 프레임을 그리지 않는다.

버튼 최소 터치 영역은 휴대폰 48×48, 차량 64×64를 제품 기본값으로 사용한다. 다중 버튼 간 최소 간격 12. 최소 높이를 고정 높이로 취급하지 말고 글자 확대 시 늘어나게 한다. 비활성·로딩·눌림 상태를 모두 제공한다.

## 3 앱 창 크기 기반 반응형

차량의 전체 디스플레이 픽셀 수가 아닌 **우리 앱에 할당된 실제 창의 너비와 높이**로 결정한다. Driving view·시스템 상태줄·하단 GNB는 OS 소유이며 앱이 가리거나 직접 재현하지 않는다. 3분할은 공식 가이드의 Driving view + 앱 창 2개 구성을 참고한다. 고정 1/3 폭을 코드에 넣지 않는다.

차량 모드는 빌드 대상·지원 기능으로 구분한다. 창이 좁다는 이유로 휴대폰 화면으로 전환하지 않는다.

```text
Pleos 레이아웃 선택 우선순위
1. safe-area 적용 후 usableHeight < 420 → short
2. usableWidth < 600 → narrow
3. 그 외 → wide
```

| 모드 | 배치 | 유지할 정보 | 접거나 상세로 이동할 정보 |
|---|---|---|---|
| wide | 본문·장소를 좌우 배치, 대략 3:2 | 미팅명·시각·핵심 브리핑·주요 행동·간단 출처 | 긴 문서·전체 대화 |
| narrow | 하나의 세로 열, 주요 행동은 전체 폭 | 미팅명·시각·핵심 문장 2~3줄·내비 요청·종료 | 담당자 설명·파일 목록·상세 출처는 버튼 또는 주차 중 상세 화면 |
| short | 단일 핵심 메시지와 1차·종료 행동 | 짧은 미팅 식별·핵심 문장·미팅 장소로 안내·종료 | 담당자 카드·출처 목록·보조 버튼·장식 라벨 |

높이가 부족하면 브리핑을 짧은 분량으로 분절하고 `계속 듣기`로 넘긴다. 중요한 수치·부정어를 잘라 표시하지 않는다. 주행 중 긴 화면 스크롤·가로 스크롤을 핵심 동작의 전제로 하지 않는다. 주차 중 상세 정보는 일반 스크롤 화면에 표시할 수 있다.

React Native 구현:

- `useWindowDimensions()`와 화면 루트 `onLayout`으로 실측한다. safe-area inset을 적용한 contentWidth / contentHeight로 판단한다.
- 실제 콘텐츠 폭이 루트보다 작으면 해당 컨테이너의 측정값을 우선한다. 한 번 읽은 `Dimensions.get` 값으로 고정하지 않는다.
- `flex`, `flexWrap`, `minWidth: 0`과 조건부 섹션으로 재배치한다. 전체 화면 scale 변환으로 축소하지 않는다.
- 미팅·질문·브리핑 진행 상태를 화면 밖 상태 저장소에 둔다. layout 값으로 루트 컴포넌트 key를 바꾸거나 SDK를 재초기화하지 않는다.
- Manifest 방향·resize 설정과 Activity 재생성 복원은 Kotlin/Expo 설정에서 실증한다. 임의의 플랫폼 동작을 가정하지 않는다.
- 비활성 창·백그라운드에서는 불필요한 화면 갱신·폴링을 중지한다. 음성 지속 여부는 오디오 포커스와 정책에 따른다.

## 4 휴대폰 화면과 탐색

하단 탭은 일정 / 거래처 / 기록 / 설정으로 통일한다. `미팅 준비`는 일정 상세 안의 화면으로 두며, 시안의 대화 중심 하단 탭은 최종 구현 시 이 구조로 통일한다.

| 화면 ID | 필수 구성 | 행동·전환 |
|---|---|---|
| M01 시작·계정 | Google로 계속하기, 데이터 처리 안내 | 계정 선택·취소·오류 처리. 로그인 후 별도 Calendar 동의. 샘플은 별도 체험 모드 |
| M02 일정 홈 | 날짜 선택, 다음 미팅 카드, 그날 일정 목록, 연결 상태 | 일정 선택 → M03. 실제 일정이 없으면 빈 상태. 샘플은 명시적으로 분리 |
| M03 미팅 상세 | 제목·시각·장소·담당자, 요약, 자료, 소통 정보 | 준비하기 → M04, PDF 추가 → 시스템 파일 선택기, 담당자 연결 수정 |
| M04 미팅 준비 | 사용자 질문, 응답·출처, 미결 질문, 저장 확인 | 텍스트 또는 지원되는 모바일 음성 입력. 휴대폰에서 Pleos STT 호출 금지 |
| M05 거래처·담당자 | 거래처 목록→담당자, 역할·확인된 선호·이전 기록 | 초안과 확인된 기억 구분, 수정·삭제, 모호한 연결 확인 |
| M06 기록 | 미팅별 메모·후속 할 일, 출처·시각 | 저장 전 확인, 완료·수정·삭제 |
| M07 설정 | 선택 프로필·취향, Calendar·차량 연결 상태, 앱 내 안내 | QR 스캔·코드 입력·연결 기기 목록·특정 차량 해제·로그아웃·삭제 |

Google 연결과 파일 첨부 외 긴 설문은 요구하지 않는다. 프로필·첨부자료 없이도 기본 일정 브리핑이 동작한다. 실제 Google OAuth용 시스템 브라우저 사용은 웹 서비스 제작과 별개다.

## 5 Pleos 화면과 탐색

| 화면 ID | 구성·행동 |
|---|---|
| P01 계정 연결 | 주차 중 QR·일회용 코드·만료 표시. 휴대폰에서 요청 확인·승인. 대기·거절·취소·만료·새 코드 상태 제공. Google 비밀번호 입력 없음 |
| P02 미팅 선택 | 다음 일정·시간·장소, 준비하기. 일정이 여러 개면 최소 후보 선택. 자동 발화 금지 |
| P03 브리핑 | 핵심 쟁점·근거 있음 표시, 장소로 안내·종료. wide / narrow / short 적용 |
| P04 추가 질문 | Gleo → 앱 Action → 관련 근거·맥락 조회 → Callback. 원문 전체 대화 수신을 전제하지 않음 |
| P05 목적지 확인 | 정확한 장소 이름·주소, 사용자 확인 후 NaviHelper 요청. 성공은 이벤트로 확인 |
| P06 주차장 후보 | 이름·위치·확인된 운영 정보·데이터 시각. 빈자리 정보 없으면 미확인. 선택 후 P05 |
| P07 기록 | 사용자가 실행할 때만 음성 메모, 확인 후 저장. 주행 제한 시 허용 범위로 축소 |

별도 미디어 플레이어나 음악 추천을 추가하지 않는다. 음성 파형은 실제 듣기·출력 상태와 연결하고, 대기 화면에서 계속 움직이지 않는다. Gleo의 시스템 UI와 앱 UI에서 동시에 마이크 활성화를 요구하지 않는다.

## 6 공통 컴포넌트와 문구

- `MeetingCard`: 일정 ID, title, startAt, location, contactName, analysisState. 하나의 카드에 주요 행동 1개.
- `BriefingPanel`: 핵심 문장·불확실성·간단 출처. 미확인 내용은 추측하여 채우지 않는다.
- `EvidenceReference`: 문서명·페이지. 서버의 실제 evidence만 표시한다. 주행 중 상세 문서 열기는 제한 상태를 반영한다.
- `DocumentRow`: 파일명·페이지 수(확인 시)·상태·재시도. 업로드 진척과 AI 분석 완료를 구분한다.
- `ContactContext`: 담당자 역할·관찰·출처·날짜·확인 상태. “보수적 성격” 대신 “이전 미팅에서 대응 시간을 질문함”.
- `MemoryConfirmation`: 제안 내용과 저장 / 건너뛰기. 대화당 확인 질문은 최대 2개.
- `DestinationConfirmation`: 장소·주소·안내 / 취소. AI 답변만으로 내비게이션을 자동 변경하지 않는다.
- `PrivacyNotice`: 수집 목적·외부 AI 전송 안내·선택 동의·삭제 경로. 앱 내부에서 재열람.

문구 예: “자료를 분석하고 있어요”, “첨부자료에서 유지보수 비용을 확인하지 못했어요”, “요청서 2쪽과 제안서 8쪽의 납기가 달라요”, “이 내용을 다음 미팅에도 참고하도록 저장할까요?”.

대화 초안·샘플 문서는 샘플이라고 표시한다. HTML의 날짜·이름·파일·주소는 모두 시안용 데이터이며 실제 캘린더 정보로 간주하지 않는다.

## 7 상태와 오류

| 상태 | 표시·복구 |
|---|---|
| 일정 로딩·비어 있음 | 로딩 표시, 이후 “예정된 미팅이 없어요”. 빈 상태를 샘플로 몰래 대체하지 않음 |
| Google 연결 해제·권한 거절 | 연결 필요 설명, 휴대폰에서 다시 연결. 차량에서 긴 로그인 입력 유도 금지 |
| 업로드·분석 중 | 업로드 진척과 queued / processing 분리, 일정 준비는 계속 가능 |
| 분석 실패·형식 제한 | 실패 이유·허용 형식과 한도, 재시도 또는 삭제 |
| 근거 부족·조건 충돌 | 미확인 표시·문서 출처·확인할 질문, AI 확신도 점수는 임의 생성하지 않음 |
| 서버 지연·단절 | 캐시 자료와 갱신 시각, 새 분석 불가 안내. Gleo 요청 무한 대기 금지 |
| 음성 포커스 상실 | 실제 재생 중단·상태 갱신, 복귀 시 정책에 맞춰 재개 |
| 데이터 삭제 | 확인 후 요청, 성공 시 관련 기록·캐시 제거. 실패 시 삭제 완료로 표시 금지 |
| 창 변경·재생성 | 선택 미팅·질문 범위·브리핑 위치 복원, 중복 메모·내비 요청 금지 |

## 8 구현 파일 책임

앱 저장소 `D:\react-expo\preve` 안에서 다음 책임을 분리한다. 실제 폴더명은 기존 코드와 충돌하지 않게 조정 가능하다.

```text
src/theme/                 색·간격·타이포 토큰
src/features/meetings/     일정·자료·준비 화면
src/features/contacts/     거래처·소통 프로필
src/features/memory/       업무 기록과 저장 확인
src/platform/              mobile / pleos 기능 어댑터
src/components/            공통 버튼·상태·근거 컴포넌트
src/api/                   OpenAPI 생성 클라이언트·인증 래퍼
modules/pleos-bridge/      Kotlin SDK·Intent·창/주행 이벤트 연결
plugins/                   빌드별 Manifest·권한·의존성 구성
```

서버는 `D:\docker\node_server\preve_server`의 별도 Git. Node.js·TypeScript, MySQL, PM2. UI는 서버 비밀키·DB 주소를 알지 않고 API를 호출한다. mock / live 어댑터는 명시적으로 구분한다. 자동 장기 기억 생성은 사용자 확인을 거친다.

## 9 완료 기준과 테스트 크기

논리 크기 기준 초기 테스트: mobile 360×800 / 412×915, pleos wide 960×600, narrow 420×720 / 360×640, short 640×360 / 420×360. 이는 공식 차종 해상도가 아닌 제품 테스트 입력이다. 실제 에뮬레이터의 window·밀도·inset으로 다시 검증한다.

1. 모든 크기에서 가로 넘침·겹침·버튼 잘림 없음. long title·긴 한국어 이름·글자 배율 1.3 포함.
2. wide ↔ narrow ↔ short 전환 후 같은 미팅·대화 범위 유지. 회전·Activity 재생성도 검증.
3. 좁거나 낮아져도 글자를 전체 축소하지 않고 핵심 브리핑·안내·종료 기능 유지.
4. 주행 제한 상태에서 로그인·편집·긴 자료 보기 제한, 오디오 포커스 상실 시 중단.
5. 홈에서 일정 선택 → PDF 연결 → 분석 상태 → 준비 대화 → 목적지 확인의 주요 흐름 작동.
6. 파일·데이터·연결 오류 시 위 상태 표의 복구 행동 제공. 임의의 성공 응답 금지.
7. 화면 읽기 라벨·초점 순서·텍스트 배율 검증. 색상 외 라벨로 상태 구분.
8. 프리뷰의 viewport 선택 컨트롤·기기 프레임·시안 안내는 실제 제품에 넣지 않음.
